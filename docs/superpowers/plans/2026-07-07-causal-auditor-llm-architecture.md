# Causal Auditor LLM Architecture Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an independent Causal Auditor LLM layer so causal implications are judged by an LLM while local code stays limited to mechanical evidence consistency.

**Architecture:** Insert `causal_audit` between evidence interpretation and answer synthesis. Build a compact `causal_evidence_dossier` from existing intent, evidence brief, and primary pattern evidence. Feed the dossier and auditor output into answer synthesis, repair, final summary, and Answer Package admin audit.

**Tech Stack:** Python, LangGraph, unittest, existing OpenAI-compatible LLM adapter, existing WAJE Answer Package JSON artifacts.

## Global Constraints

- Follow `docs/causal-auditor-llm-architecture.md`.
- Do not add dependencies.
- Do not make local code decide whether a causal implication is insightful.
- Local code may only enforce mechanical consistency: SQL safety, permission, schema, metric/time/grain validity, evidence refs, numeric consistency, and causal wording no stronger than the Causal Auditor classification.
- Causal Auditor output must be generated by an LLM task named `causal_audit`.
- User-facing narrative fields must be concise Simplified Chinese.
- Do not expose raw SQL, hidden chain-of-thought, internal ids, enum tokens, evidence refs, or provider metadata in business-reader text.
- Keep the existing prompt-output JSON style and FakeLLM test pattern.
- Use TDD: write a failing test, run it, implement the smallest passing code, rerun tests.
- Do not commit from this dirty workspace unless the controller explicitly instructs you to commit.

def _audit_causal_implications(state: WorkflowState) -> WorkflowState:
    _maybe_force_node_failure(state, "audit_causal_implications")
    dossier = _build_causal_evidence_dossier(state)
    state["causal_evidence_dossier"] = dossier
    state["causal_audit"] = _invoke_llm(
        state,
        "causal_audit",

Implement `_build_causal_evidence_dossier` with existing helpers and no new dependencies:

```python
def _build_causal_evidence_dossier(state: WorkflowState) -> dict[str, Any]:
    intent = state.get("intent", {})
    pattern = _pattern_evidence(state)
    payload = pattern.get("typed_payload", {})
    limitations = list(state.get("evidence_brief", {}).get("limitations", ()))
    return {
        "target_claim": intent.get("target_claim", ""),
        "question_family": intent.get("question_family", ""),
        "scope": intent.get("scope", ""),
        "time_window": intent.get("time_window", ""),
        "observed_pattern": {
            "metric": _business_metric_label(state),
            "pattern_family": payload.get("pattern_family") or intent.get("pattern_family"),
            "effect_size": payload.get("median_uplift"),
            "direction_ratio": payload.get("direction_ratio"),
            "comparable_periods": payload.get("comparable_periods"),
            "strength": pattern.get("strength"),
            "wording_limit": pattern.get("wording_limit"),
            "limitations": limitations,
        },
        "temporal_order": {
            "known": False,
            "summary": "当前证据未提供可验证的先后顺序。"
        },
        "comparison_context": {
            "baseline": _baseline_label(state),
            "target": _target_label(state),
            "control_or_counterfactual": "none",
            "summary": "当前证据来自已执行的业务对比路径。"
        },
        "segment_consistency": [],
        "event_overlap": [],
        "alternative_explanations": [],
        "negative_evidence": limitations,
        "missing_evidence": [
            "缺少独立因果验证、对照或机制证据。"
        ],
        "data_limits": limitations,
    }
```
