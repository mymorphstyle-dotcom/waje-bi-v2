# 2026-07-20：业务参考持续交付与人工审计闭环

## 状态

Accepted。

本决定覆盖 2026-07-17 工作流 ADR 中关于 narrative verifier 拥有发布否决权、
focused retry 自动改写、`verified/withheld` 发布状态和“仅发布核验通过段落”的内容。
权限、SQL 安全、数据合同、固定敏感输出、证据来源、claim provenance、持久化完整性
和客户可见性仍是强制边界。

## 产品判断

WAJE BI Agent 生成的内容定位为可追溯的业务参考。每次已进入分析的用户请求都应得到
明确终局响应：交付业务参考，或如实说明本次运行因真实故障无法生成参考。业务质量核验
持续运行并完整留痕，但不暂停交付、不删除 LLM 原文，也不自动触发局部改写。

核验结果服务于三个后台用途：人工复核与标注、训练和评测数据清洗、经治理批准后的通用
改进。单次核验发现不能直接升级为运行时规则，不能依靠关键词规则修正文案。

## 两条链

```text
用户问题
→ 意图与计划
→ 查询与证据结算
→ LLM 洞察和业务表达
→ 固定客户安全投影
→ 业务参考交付

同一份持久化结果
→ 后台核验发现
→ Workbench 人工复核
→ 评分、原因、标签和清洗决定
→ 独立修订样本或评测样本
→ 人工批准的通用能力改进
```

第一条是客户交付链，第二条是质量学习链。两条链共享 run、narrative、claim、evidence
和 digest 身份。质量学习链不能回写并伪装首次交付；需要修订时创建新的、可追溯的
revision。

## 发布边界

以下情况可以阻止不安全内容进入客户投影：

- 身份、权限或固定敏感输出边界失败；
- SQL 安全、数据合同或持久化完整性失败，导致无法形成可信的本次运行记录；
- 没有形成可交付 narrative，或交付基础设施真实失败。

后台核验发现、洞察质量评分、表达完整性、解释深度、行动建议质量和潜在幻觉风险都作为
审计信号保存。它们可以进入 Workbench、抽样队列和人工修订流程，不能映射为
`publication_withheld`，也不能让正常用户看到内部错误码。

## Human-in-the-loop 合同

每个已发布 narrative 默认进入 `pending` 人工复核状态。Workbench 允许具名审核人：

1. 查看原始业务参考、claim/evidence 关系、核验发现和完整技术故障；
2. 按解释价值、新颖性、决策用途、竞争假设、不确定性和可行动性六个维度评分；
3. 记录人工原因、结构化标签和 `reviewed` / `revision_requested` 决定；
4. 发起独立 narrative revision，保留原始版本和所有 provider 响应；
5. 将经过清洗的数据纳入 eval 候选；
6. 只有通用模式、人工验证、业务 owner 与系统 owner 共同批准后，才形成新的合同、提示词
   或运行时安全策略。

正常用户页不展示核验通过率、内部组件名、技术状态枚举、UUID 或审核队列。用户可见内容
保持业务问题、真实进展、业务参考、证据范围、限制和下一步行动。

## 前端交互

主页面使用 Codex 风格的连续对话流：用户问题、已确认的持久化进展、一次性澄清、业务
参考和错误恢复按时间顺序出现。主页面不使用工作流画布或阶段卡片。进展只来自持久化
checkpoint；历史事件只负责回放，不能恢复控件操作权。

客户状态在任意时刻只有一个：`idle`、`working`、`needs_input`、`completed`、
`completed_with_limits`、`failed`。浏览器中的 run/thread/dispatch handle 只负责传输和
幂等恢复，不进入 DOM。

Workbench 继续承担完整技术审计、关系图、核验发现、人工复核与修订入口。

## 实施顺序

1. 删除 verifier 到发布阻断和自动 focused retry 的运行路径，收敛发布状态为
   `not_ready → composing → ready → published`。
2. 发布所有通过固定客户安全投影的 narrative blocks，并把核验报告作为后台审计记录。
3. 将客户 API/SSE 收敛为单一强类型 conversation projection；历史事件不能决定当前操作。
4. 主页面切换为连续对话流，进展只显示已确认 checkpoint。
5. Workbench 接入人工复核状态、六维评分、原因和修订请求。
6. 删除 `publication_withheld`、`verified` 发布态、`accepted_blocks` 客户字段和对应旧测试。

## 验收

- verifier 拒绝一个或多个业务段落时，客户业务参考仍然创建、持久化并交付；
- 敏感输出发现仍能从客户投影中排除相应内容；
- 后台可以定位 verifier 报告、原始 narrative、provider 响应和人工复核记录；
- 运行不会因质量发现自动调用 writer；
- 真实 narrative、持久化或交付失败会形成客户可读的失败终局；
- 刷新、多标签页和断线恢复都以最新持久化客户状态为准；
- 主页面 DOM 不出现核验状态、内部组件名、UUID 和 snake_case 错误；
- 人工修订形成新 revision，首次交付记录保持不可变。
