# Phase 3 Runtime Readiness Checklist

Status: runtime-readiness handoff checklist for the later semantic compiler runtime.

Related: [Completion status](phase-3-completion-status.md), [Runtime handoff](phase-3-runtime-handoff.md), [Semantic compiler dry-run](phase-3-semantic-compiler-dry-run.md)

Scope: checklist, validator spec, gate matrix, and gap preservation only. This document does not implement runtime, SQL, database access, LangGraph execution, final table structure, frontend, real capability execution, or business conclusions.

## Readiness State Legend

| State | Meaning |
| --- | --- |
| `covered_by_contract_harness` | Current fixture, dry-run generator, contract harness, or existing validators already check the contract-level mapping. |
| `needs_runtime_validator` | Runtime must add a deterministic validator before moving past the related gate. |
| `needs_owner_decision` | Business/data/engineering owner must confirm policy, source, schema, permission, or evidence boundary before execution or publication. |
| `out_of_scope_for_phase_3` | Kept blocked or degraded in Phase 3. It cannot be promoted by this checklist. |

## Harness Bundle Boundary

The current contract harness builds one bundle per semantic compiler fixture. A later runtime can use the bundle shape as its input/output acceptance surface, but it must add runtime validators before any SQL planning, execution, typed payload values, result refs, persisted artifacts, or Answer Package publication.

Runtime readiness starts from these current guarantees:

- `tools/evals/run-semantic-compiler-contract-harness.rb` builds 8 bundles from the fixture set.
- `tools/evals/generate-semantic-compiler-dry-run.rb` maps accepted graph nodes to semantic query requests, response skeletons, evidence envelopes, and Answer Package claim groups.
- `tools/runtime/run-semantic-compiler-dry-run-artifact.rb` persists 8 local no-SQL dry-run artifacts from fixture or harness input.
- `tools/runtime/validate-semantic-compiler-dry-run-artifacts.rb` validates local artifact persistence, non-runtime boundaries, path refs, evidence refs, and support/backlog/limitation traceability.
- `tools/evals/validate-semantic-compiler-dry-run.rb` checks dry-run refs, query execution boundary flags, mapping assertions, blocked paths, and enum values.
- `tools/evals/validate-semantic-compiler-fixtures.rb` checks fixture fields against capability support, backlog refs, limitation refs, typed payload names, and coverage.
- Every bundle includes `non_runtime_notice`; no bundle contains SQL, database rows, runtime connection, real typed payload values, or real business conclusions.

## Owner Decision Queue

Runtime implementation should stop for owner input before crossing gates when any item below is needed:

- Physical SQL schema, final runtime API, final persistence table structure, or ClickHouse/Postgres binding.
- Masking, raw identifier output, or individual-user analysis.
- Cross-source date reconciliation.
- Net revenue, adjusted revenue, refund, reversal, chargeback, cancellation, or adjustment-risk analysis.
- Campaign spend, exposure, control, product operation events, incident sources, or causal impact wording.
- Gameplay paid_amount linkage, gameplay exposure/click, gameplay payment metrics, or order-to-gameplay attribution.
- New external evidence connector, live web/news/forum/media crawling, or AnySearch-like ingestion; current-version requests for extra external information become later-phase connector backlog.
- Promotion of any `missing_contract`, `unsupported_grain`, `permission_limited`, or `out_of_scope_for_now` path into stronger support.
